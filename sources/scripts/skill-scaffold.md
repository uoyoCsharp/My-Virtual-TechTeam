# Skill Scaffold Script - Full Reference

> **This file is the authoritative usage reference for `skill-scaffold.cjs`.**
> Read this file before calling the script. Do NOT read the `.cjs` or `.js` source to learn flag names or semantics.

The scaffolder materializes a **custom skill** into every installed AI platform and registers it. It is the only supported way to create or update a custom skill: never create platform skill directories or edit `registry.yaml` by hand.

## Why this script exists

Framework skills are generated by the installer, which rewrites the canonical `.claude/skills/` prefix per platform. Custom skills are created at runtime and bypass that step, so hardcoding any platform's skills directory in skill content breaks every other platform. This script owns the platform id → skills directory mapping (from `.mvtt/.mvtt-manifest.json#platformSkillDirs`) so the content layer never has to.

## Prerequisites

- Run from inside an MVTT project (the script locates the root containing `.mvtt/`).
- `.mvtt/.mvtt-manifest.json` and `.mvtt/registry.yaml` must exist (`mvtt install`).
- The staged skill directory must contain a `SKILL.md` whose frontmatter `name` matches `--name` and whose `description` is non-empty.

## Command: scaffold

```bash
node .mvtt/scripts/skill-scaffold.cjs scaffold \
  --name <skill-name> \
  --description "<third-person description>" \
  [--from <staged-skill-dir> | --body <SKILL.md>] \
  [--template <name>-output.md --template-body <template-file>] \
  [--resource references,scripts,assets] \
  [--platforms all|<id>,<id>] \
  [--role <role>] [--category <category>] \
  [--dry-run] [--force]
```

| Flag | Required | Semantics |
|---|---|---|
| `--name` | yes | Lowercase kebab-case matching `^[a-z][a-z0-9-]*$`. Must not collide with a registered skill unless `--force`. |
| `--description` | yes | Third-person trigger description stored in `registry.yaml`. |
| `--from` | one of | Staged directory containing `SKILL.md` plus optional bundled resources (`references/`, `scripts/`, `assets/`). Preferred: copies the whole tree. |
| `--body` | one of | Single `SKILL.md` file. Use when there are no bundled resources. |
| `--template` | no | Template basename, e.g. `proj-foo-output.md`. Written to `.mvtt/skills/_templates/` and referenced from the registry entry. |
| `--template-body` | with `--template` | File whose content becomes the template (headings-only document structure). |
| `--resource` | no | Comma list of resource directories to create (`assets`, `references`, `scripts`). |
| `--platforms` | no | `all` (default) writes to every installed platform; a comma list restricts the write set. |
| `--role` / `--category` | no | Optional metadata echoed into the registry entry and the JSON summary. |
| `--dry-run` | no | Print the plan as JSON without touching disk or the registry. |
| `--force` | no | Replace an already-registered skill and its files. |

Behaviour:

- Writes identical bytes to **every** target platform's skills directory.
- Creates the registry entry with `custom: true` **last**, after all skill files succeed, so a failure cannot leave a phantom registry entry.
- Backs up the previous registry to `.mvtt/.backup/registry-<timestamp>.yaml` before rewriting.
- On a fresh-creation failure, removes the skill directories it created (no rollback when replacing an existing skill with `--force`).
- Warns (does not fail) when `SKILL.md` references another platform's skills directory that is not installed, or when the body exceeds ~5000 words.

## Command: sync

```bash
node .mvtt/scripts/skill-scaffold.cjs sync \
  --name <skill-name> \
  [--from <dir> | --body <SKILL.md>] \
  [--platforms all|<id>,<id>] \
  [--dry-run]
```

Use after editing a custom skill so every installed platform gets the same content again.

| Flag | Required | Semantics |
|---|---|---|
| `--name` | yes | Registered custom skill to sync. Fails if the skill is not in `registry.yaml`. |
| `--from` | no | Source directory to mirror (SKILL.md plus bundled resources). |
| `--body` | no | Source `SKILL.md` only. |
| `--platforms` | no | `all` (default) or a comma list. |
| `--dry-run` | no | Print the plan without writing. |

When neither `--from` nor `--body` is given, the first installed platform that has the skill provides the source (useful for adopting a skill that was previously created on one platform only). `sync` never edits the registry.

## Output interpretation

- **Exit 0**: stdout is a single-line JSON object.

  `scaffold`:

  ```json
  {
    "ok": true,
    "command": "scaffold",
    "name": "proj-foo",
    "platforms": [
      { "id": "claude", "skillDir": ".claude/skills", "files": [".claude/skills/proj-foo/SKILL.md"] },
      { "id": "cursor", "skillDir": ".cursor/skills", "files": [".cursor/skills/proj-foo/SKILL.md"] }
    ],
    "registry": { "path": ".mvtt/registry.yaml", "entry": { "description": "...", "custom": true }, "backup": ".mvtt/.backup/registry-....yaml" },
    "template": null,
    "resources": [],
    "warnings": [],
    "wordCount": 420
  }
  ```

  `sync`:

  ```json
  {
    "ok": true,
    "command": "sync",
    "name": "proj-foo",
    "source": ".claude/skills/proj-foo",
    "platforms": [
      { "id": "claude", "skillDir": ".claude/skills", "files": [".claude/skills/proj-foo/SKILL.md"] }
    ],
    "warnings": []
  }
  ```

- **Exit 1**: stderr explains the failure (missing manifest/registry, invalid name, frontmatter mismatch, registry collision, invalid YAML, filesystem error). Do not infer partial success and do not retry by writing files manually — the script rolls back on failure; surface the error.

Report the `platforms[].files` list to the user as the skill location, and surface any `warnings` entries.
